01 / Context

O evaluare adaptată aplicației.

Trei obiective: familiarizare cu două instrumente, scrierea scripturilor și verificarea unei aplicații personale.

Hand-Made — magazin de artizanat

Site de prezentare pentru ceramică, textile, bijuterii și produse din lemn. Include pagini pentru produse, ateliere, galerie, informații și contact.

https://popovmaxim-netizen.github.io/Hand-Made/

Tehnologii observate

HTML, CSS, JavaScript, Bootstrap 5.3.3 și Font Awesome 6.5.0; găzduire GitHub Pages.

Comportament verificat în sursă

Formularul este validat în js/validation.js. La succes apare un mesaj fix și formularul se resetează; în acest flux nu apare o cerere către un server.

Ce intră în testare

Paginile publice proprii, antetele, codul disponibil și validarea contactului. În sursele inspectate nu s-a identificat un backend pentru formular. Testele SQL Injection, JWT, autentificare și baze de date nu sunt aplicabile fluxului verificat. HTTPS protejează transportul; validarea JavaScript poate fi ocolită.

02 / Familiarizarea cu instrumentele

SecurityHeaders + Postman.

Un instrument pentru configurarea răspunsurilor. Un instrument pentru cereri și teste JavaScript repetabile.

Instrumentul 1 · Online

SecurityHeaders

Analizează antetele HTTP de securitate ale unei pagini și prezintă configurările identificate. Nu verifică validarea formularului sau codul JavaScript.

  1. Deschide securityheaders.com.
  2. Lipește adresa completă Hand-Made, inclusiv /Hand-Made/.
  3. Pornește analiza și verifică URL-ul final evaluat.
  4. Examinează HSTS, CSP, X-Content-Type-Options, X-Frame-Options și Referrer-Policy.
  5. Păstrează captura cu URL, dată și rezultatele reale.

Analiza în interfața SecurityHeaders nu a fost executată la generarea raportului. Nota platformei se completează după rularea ta.

Instrumentul 2 · Cerut

Postman

Trimite cereri HTTP și execută scripturi asupra răspunsului. Pentru Hand-Made folosim cereri GET și aserțiuni pentru statusuri și antete.

  1. Deschide Postman în browser sau aplicația desktop.
  2. Importă colecția descărcată din această pagină.
  3. Verifică variabila de colecție baseUrl, care include slash la final.
  4. Deschide o cerere și apasă Send.
  5. Vezi scripturile în Scripts → Post-response și rezultatele în Test Results.

Dacă varianta web nu poate trimite cererea prin agentul curent, selectează Desktop Agent sau folosește aplicația desktop. Nu dezactiva verificarea certificatelor TLS.

03 / Scripturi de testare

Colecție gata de importat.

Cele 5 cereri folosesc rute reale: pagina principală, Produse, Ateliere, Contact și o pagină inexistentă. Prima cerere conține testele T01–T06; ultima conține T07. T08–T10 se verifică în browser sau în cod.

baseUrl = https://popovmaxim-netizen.github.io/Hand-Made/

Un test roșu este un rezultat de analizat.

Antetele lipsă vor produce aserțiuni eșuate. Nu modifica aserțiunile pentru a forța culoarea verde. Înregistrează diferența față de baseline și explică limita găzduirii. Rezultatele din Postman se completează după rulare; raportul nu pretinde că acea rulare a avut loc.

Exemplu complet: verificarea paginii principale
pm.test("Pagină publică disponibilă, HTML", function () {
  pm.response.to.have.status(200);
  pm.expect(pm.response.headers.get('Content-Type') || '').to.match(/text\/html/i);
});

pm.test("T01 — URL HTTPS și HSTS cu max-age pozitiv", function () {
  pm.expect(pm.variables.replaceIn(pm.request.url.toString())).to.match(/^https:\/\//i);
  const hsts = pm.response.headers.get('Strict-Transport-Security') || '';
  const match = hsts.match(/(?:^|;)\s*max-age\s*=\s*(\d+)/i);
  pm.expect(match, 'Directiva max-age lipsește').to.not.equal(null);
  pm.expect(Number(match[1])).to.be.above(0);
});

pm.test("T02 — CSP restrictivă prezentă (baseline de întărire)", function () {
  const csp = pm.response.headers.get('Content-Security-Policy') || '';
  pm.expect(csp, 'CSP absentă').to.not.equal('');
  pm.expect(csp).to.match(/(?:^|;)\s*(default-src|script-src)\s+/i);
  // Prezența nu validează întreaga politică. Revizuiește directivele manual.
});

pm.test("T03 — X-Content-Type-Options: nosniff", function () {
  const value = pm.response.headers.get('X-Content-Type-Options') || '';
  pm.expect(value.trim().toLowerCase()).to.equal('nosniff');
});

pm.test("T04 — Politică de încadrare restrictivă", function () {
  const csp = pm.response.headers.get('Content-Security-Policy') || '';
  const xfo = (pm.response.headers.get('X-Frame-Options') || '').trim().toUpperCase();
  const match = csp.match(/(?:^|;)\s*frame-ancestors\s+([^;]+)/i);
  const restrictiveCsp = !!match && ["'none'", "'self'"].includes(match[1].trim());
  pm.expect(restrictiveCsp || ['DENY', 'SAMEORIGIN'].includes(xfo)).to.equal(true);
  // Baseline ales: self/none sau XFO. Alte allowlist-uri cer analiză manuală.
});

pm.test("T05 — Referrer-Policy explicită conform baseline-ului", function () {
  const value = (pm.response.headers.get('Referrer-Policy') || '').trim().toLowerCase();
  pm.expect(['no-referrer', 'same-origin', 'strict-origin', 'strict-origin-when-cross-origin']).to.include(value);
  // Lipsa antetului poate lăsa în vigoare politica implicită a browserului.
});

pm.test("T06 — Fără combinație CORS wildcard + credențiale", function () {
  const origin = pm.response.headers.get('Access-Control-Allow-Origin');
  const credentials = (pm.response.headers.get('Access-Control-Allow-Credentials') || '').trim().toLowerCase();
  pm.expect(origin === '*' && credentials === 'true').to.equal(false);
  // Pentru HTML public, wildcard-ul singur nu indică o vulnerabilitate.
  // Testul nu dovedește securitatea unui API sau a autorizării.
});

Validarea formularului de contact

https://popovmaxim-netizen.github.io/Hand-Made/contact.html

Rezultat așteptat

Emailul invalid și bugetul ≤ 0 sunt respinse. Datele valide declanșează mesajul de succes.

Rezultat observat · 16.10.2026

validation.js a fost executat cu un DOM simulat: emailul maxim@, bugetul 0 și -10 sunt respinse; datele valide afișează succesul. Confirmarea vizuală în browser rămâne de făcut.

  2. Introdu maxim@ la email; apasă butonul de trimitere și verifică eroarea.

  4. Cu date valide, verifică mesajul de succes și fila Network. Mesajul singur nu dovedește trimiterea unei comenzi.

Date cu markup și posibila interpretare HTML

https://popovmaxim-netizen.github.io/Hand-Made/contact.html

Rezultat așteptat

Datele utilizatorului nu sunt interpretate ca HTML executabil.

Rezultat observat · 16.10.2026

În simulare, numele <b>TEST_HANDMADE</b> trece regula de lungime. În fișierul validation.js verificat nu este redat în DOM: se afișează un mesaj fix și se resetează formularul. Acceptarea șirului nu dovedește XSS.

În browser, introdu markerul inofensiv <b>TEST_HANDMADE</b> la nume și completează restul corect. Urmărește dacă markerul ajunge în pagină ca text sau markup. Verifică separat orice alt flux care afișează date introduse. Acest marker verifică interpretarea HTML, nu executarea JavaScript.

T10Constatare în cod

Resurse externe și SRI

HTML-ul paginii principale

Rezultat așteptat

Fișierele externe cu versiune fixă au integrity și crossorigin atunci când sunt distribuite cu suport SRI.

Rezultat observat · 16.10.2026

Legăturile Bootstrap 5.3.3, Font Awesome 6.5.0 și scriptul Bootstrap nu au atribut integrity. SRI este o măsură de reducere a riscului de alterare a dependențelor; nu s-a demonstrat compromiterea lor.

Deschide sursa paginii și caută cdn.jsdelivr.net, cdnjs.cloudflare.com și integrity. Folosește hash-ul publicat pentru versiunea exactă sau generează-l din fișierul verificat; nu inventa hash-uri SRI.

Limita verificării

06 / Îmbunătățiri recomandate

De la constatare la remediere.

  1. CSP și protecția iframe. Definește o politică pe baza resurselor reale. Pe GitHub Pages nu există o setare obișnuită per proiect pentru antete HTTP arbitrare; pentru control complet este necesară o găzduire sau un proxy care permite configurarea lor. frame-ancestors trebuie trimis ca antet HTTP, nu prin meta.
  2. Antete explicite. Configurează X-Content-Type-Options: nosniff și o politică Referer adecvată acolo unde platforma permite. O meta Referrer-Policy poate fi o alternativă pentru pagina HTML, dar nu înlocuiește toate antetele.
  3. Integritatea dependențelor. Adaugă SRI pentru resursele externe fixe sau găzduiește local fișierele verificate. Păstrează versiunile actualizate și retestează după schimbare.
  4. Formularul. Prezintă clar caracterul demonstrativ al trimiterii. Dacă se adaugă un backend, validează și pe server toate datele; mesajul de succes trebuie afișat după un răspuns real de succes.
  5. Redarea datelor. Pentru afișarea textului introdus folosește textContent. Evită introducerea datelor nevalidate în innerHTML. Repetă testele după orice funcție nouă.

Concluzie

Site-ul Hand-Made este accesibil prin HTTPS, transmite HSTS și răspunde cu HTTP 404 pentru resursa inexistentă verificată. În răspunsul paginii principale lipsesc mai multe antete de întărire; în HTML-ul inspectat, dependențele CDN fixe nu au SRI.

Codul formularului respinge anumite date invalide în simularea executată, însă confirmarea în browser rămâne necesară. Fluxul verificat afișează un mesaj local de succes și nu conține trimitere către un server. Acceptarea unui șir cu markup nu a demonstrat XSS.

SecurityHeaders și Postman sunt pregătite pentru verificări repetabile. După executarea lor, se atașează capturile și se compară rezultatele reale cu observațiile din acest raport.
